# Task Manager

Небольшое приложение для управления задачами. Выполнено как тестовое задание на позицию Junior Frontend Developer.

## Возможности

- просмотр списка задач (название, статус, приоритет, дата создания);
- создание задачи через модальное окно;
- редактирование задачи в той же форме;
- удаление задачи с подтверждением;
- быстрая смена статуса прямо на карточке (с оптимистичным обновлением);
- фильтрация задач по статусу (синхронизирована с URL);
- поиск по названию с debounce;
- страница с подробной информацией о задаче (`/tasks/:id`);
- состояния загрузки, ошибки с кнопкой «Повторить» и пустого списка;
- адаптивная вёрстка

## Запуск

```bash
npm i
npm run dev
```

`npm run dev` одновременно запускает клиент (Vite, http://localhost:5173) и мок-сервер API (json-server, http://localhost:3001). Запросы приложения к `/api/*` проксируются на мок-сервер через конфигурацию Vite.

## Технологии

- **React 19** — функциональные компоненты и хуки;
- **TypeScript** (strict, без `any`);
- **Vite** — сборка и dev-сервер;
- **TanStack Query** — работа с API, кэширование, мутации;
- **React Router** — маршрутизация;
- **react-hook-form + zod** — валидация форм;
- **json-server** — мок-сервер API;
- **CSS Modules + CSS-переменные** — стилизация;
- **lucide-react** — иконки;
- **ESLint + Prettier** — качество и форматирование кода.

## Архитектура

```
src/
├── components/   # переиспользуемые UI-компоненты (каждый в своей папке)
├── pages/        # страницы: список, детальная, 404
├── hooks/        # бизнес-логика: запросы, мутации, фильтры, диалоги
├── schemas/      # схемы валидации (zod)
├── types/        # типы модели задачи
├── utils/        # метки статусов/приоритетов, форматирование дат
├── styles/       # глобальные стили и CSS-переменные дизайн-системы
├── App.tsx       # маршруты
└── main.tsx      # точка входа
```

Бизнес-логика отделена от UI: запросы и мутации вынесены в хуки (`useTasks`, `useTask`, `useCreateTask`, `useUpdateTask`, `useUpdateStatus`, `useDeleteTask`), состояние фильтров и диалогов — в хуки `useTaskFilters` и `useTaskDialogs`. Страницы подключают хуки и передают данные в компоненты пропсами; переиспользуемые формы и диалоги (`TaskForm`, `TaskItem`, `ConfirmDeleteDialog`) используют хуки мутаций напрямую.

## Принятые технические решения

- **TanStack Query вместо ручного fetch** — серверное состояние (кэш, повторные запросы, инвалидация) управляется библиотекой; все мутации инвалидируют и список, и детальную страницу (префиксы ключей `['tasks']` и `['task']`). Смена статуса на карточке обновляет кэш оптимистично с откатом при ошибке.
- **Без глобального состояния** — серверные данные живут в TanStack Query, UI-состояние (открытые модалки, фильтры) локальное. Zustand рассматривался, но отклонён: добавлять его некуда.
- **Серверная фильтрация и поиск** — json-server фильтрует по `?status=` и `title_like=`. Данные всегда соответствуют URL, фильтрация не дублируется на клиенте.
- **Фильтры и поиск в URL** — состояние фильтров живёт в query-параметрах, поэтому ссылку на отфильтрованный список можно сохранить и поделиться.
- **React Router в декларативном режиме** — данными владеет TanStack Query, маршрутизатор отвечает только за навигацию.
- **Модальные окна через createPortal** — рендерятся в `document.body`, не зависят от `overflow`/`transform` родительских контейнеров.
- **Валидация на уровне схемы** — react-hook-form с zod-resolver: одна схема `taskFormSchema` используется и для создания, и для редактирования.
- **Поиск с debounce** — запрос на сервер уходит только после паузы ввода.
- **Адаптив на CSS Grid** — карточка перестраивается по именованным областям грида: на мобильных селект статуса и кнопки действий переносятся на отдельную строку.
